Only purchase date, refund date/amount/note are user inputs to the refund command. Permit eligible fixed cost, spending, and giving purchases.

Any rejection rolls back entry, link, audit, and idempotency outcome.
4. Extend activity and destination views and frontend to record refunds from a purchase and show remaining refundable. Add synthetic unit, real PostgreSQL integration/race, and isolated browser coverage. Do not touch the personal browser or development database.
5. Run focused checks, save an explicit-path local recovery commit, then hand off for independent review. Proof and integration are orchestrator stages.
